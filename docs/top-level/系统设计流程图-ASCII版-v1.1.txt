================================================================================
                MSS AI PPT 报告生成系统设计流程图 v1.1
                    （纯ASCII文本版本 - 异步任务队列版）
================================================================================

**版本**: v1.1
**日期**: 2026-02-03
**变更**: 更新为异步任务队列架构,添加JobManager、RESTful API v1路由

最终版本：用户上传Excel → 校验 → 数据提取 → 异步任务 → AI生成 → PPT渲染 → 预览下载

================================================================================
                          【错误处理与自动重试流程】
================================================================================

┌───────────────────────────────────────────────────────────────────────────┐
│                        AI格式错误5次场景                                   │
├───────────────────────────────────────────────────────────────────────────┤
│                                                                           │
│  触发条件：AI响应JSON格式错误，已重试5次仍失败                            │
│                                                                           │
│  处理流程：                                                               │
│  ┌─────────────────────────────────────────────────────────┐             │
│  │ 1. LLMOrchestratorV2._call_and_parse_with_retry()       │             │
│  │    抛出 LLMGenerationError("AI响应格式错误，已重试5次") │             │
│  │                                                         │             │
│  │ 2. 后台任务捕获异常                                     │             │
│  │    任务状态更新为: failed                               │             │
│  │    保存error: "AI响应格式错误,已重试5次"                │             │
│  │                                                         │             │
│  │ 3. JobManager检查是否应重试                             │             │
│  │    retry_count < 3? → YES                              │             │
│  │                                                         │             │
│  │ 4. 指数退避等待: 2^(retry_count) 秒                    │             │
│  │    retry 1: 等待2秒                                     │             │
│  │    retry 2: 等待4秒                                     │             │
│  │    retry 3: 等待8秒                                     │             │
│  │                                                         │             │
│  │ 5. 自动重新启动任务                                     │             │
│  │    _process_report_async(...) 再次执行                │             │
│  │                                                         │             │
│  │ 6. 若3次重试后仍失败                                    │             │
│  │    任务状态: failed (最终)                              │             │
│  │    WebSocket推送失败通知                                │             │
│  └─────────────────────────────────────────────────────────┘             │
│                                                                           │
│  用户体验：                                                               │
│  • 轮询任务状态时看到retry_count递增                                      │
│  • 最终失败后,可手动切换use_mock=true重新提交                            │
│                                                                           │
└───────────────────────────────────────────────────────────────────────────┘

┌───────────────────────────────────────────────────────────────────────────┐
│                     AI接口不通/Rate Limit场景                              │
├───────────────────────────────────────────────────────────────────────────┤
│                                                                           │
│  触发条件1：网络/服务不可用 (APIConnectionError, 5xx错误)                 │
│  触发条件2：请求过于频繁 (RateLimitError)                                 │
│                                                                           │
│  处理流程：                                                               │
│  ┌─────────────────────────────────────────────────────────┐             │
│  │ 1. LLMOrchestratorV2._call_openai_with_retry()          │             │
│  │    ├─ 网络错误：重试最多4次 (指数退避)                  │             │
│  │    ├─ Rate Limit：重试最多4次 (指数退避)                │             │
│  │    └─ 全部失败：抛出 LLMGenerationError                 │             │
│  │                                                         │             │
│  │ 2. 后台任务捕获异常                                     │             │
│  │    任务状态更新为: failed                               │             │
│  │    保存error信息                                        │             │
│  │                                                         │             │
│  │ 3. JobManager自动重试 (最多3次,指数退避)                │             │
│  │    同上述AI格式错误处理流程                             │             │
│  │                                                         │             │
│  │ 4. 最终失败后                                           │             │
│  │    用户可查看error详情,手动切换mock模式                 │             │
│  └─────────────────────────────────────────────────────────┘             │
│                                                                           │
│  用户体验：                                                               │
│  • GET /api/v1/jobs/{job_id} 查看失败原因                                │
│  • 看到retry_count和详细错误信息                                         │
│  • 可手动重试或切换mock模式                                              │
│                                                                           │
└───────────────────────────────────────────────────────────────────────────┘

┌───────────────────────────────────────────────────────────────────────────┐
│                         服务器重启恢复流程                                 │
├───────────────────────────────────────────────────────────────────────────┤
│                                                                           │
│  触发条件：服务器重启时,发现有processing状态的任务                        │
│                                                                           │
│  处理流程：                                                               │
│  ┌─────────────────────────────────────────────────────────┐             │
│  │ 1. app.py启动时执行 @app.on_event("startup")            │             │
│  │                                                         │             │
│  │ 2. 清理陈旧锁文件 (超过5分钟)                           │             │
│  │    cleanup_stale_locks(outputs_dir, max_age=300)       │             │
│  │                                                         │             │
│  │ 3. 清理旧任务 (超过7天)                                 │             │
│  │    job_store.cleanup_old_jobs(days=7)                  │             │
│  │                                                         │             │
│  │ 4. 清理旧会话 (超过7天)                                │             │
│  │    service.cleanup_old_sessions(max_age_hours=168)     │             │
│  │                                                         │             │
│  │ 5. TODO: 恢复processing状态的任务                      │             │
│  │    (当前未完全实现,需JobManager增强)                   │             │
│  └─────────────────────────────────────────────────────────┘             │
│                                                                           │
│  当前限制：                                                               │
│  • processing状态的任务不会自动恢复                                       │
│  • 用户需手动重新提交任务                                                 │
│  • 建议增强: JobManager在启动时检测processing任务并标记为failed          │
│                                                                           │
└───────────────────────────────────────────────────────────────────────────┘


================================================================================
                          【并发控制机制】
================================================================================

┌───────────────────────────────────────────────────────────────────────────┐
│                          Semaphore限流控制                                 │
├───────────────────────────────────────────────────────────────────────────┤
│                                                                           │
│  限制：最多3个并发LLM请求                                                 │
│                                                                           │
│  实现：                                                                   │
│  ┌─────────────────────────────────────────────────────────┐             │
│  │ llm_semaphore = asyncio.Semaphore(3)                   │             │
│  │                                                         │             │
│  │ async with llm_semaphore:                              │             │
│  │     # 获得槽位，执行LLM调用                             │             │
│  │     result = await loop.run_in_executor(...)           │             │
│  │     # 自动释放槽位                                      │             │
│  └─────────────────────────────────────────────────────────┘             │
│                                                                           │
│  场景：                                                                   │
│  • 第1-3个请求：立即获得槽位，并行执行                                    │
│  • 第4个请求：等待队列，直到前3个中有1个完成                              │
│                                                                           │
│  健康检查：                                                               │
│  GET /api/v1/system/health 返回当前并发状态：                             │
│  {                                                                        │
│    "llm_concurrency": {                                                  │
│      "max_concurrent_requests": 3,                                       │
│      "available_slots": 1,      # 当前可用槽位                            │
│      "active_requests": 2,      # 当前活跃请求                            │
│      "is_saturated": false      # 是否已满                               │
│    }                                                                      │
│  }                                                                        │
│                                                                           │
└───────────────────────────────────────────────────────────────────────────┘

┌───────────────────────────────────────────────────────────────────────────┐
│                          IP速率限制                                        │
├───────────────────────────────────────────────────────────────────────────┤
│                                                                           │
│  限制：同一IP地址 30秒内只能提交1次报告生成请求                           │
│                                                                           │
│  实现：                                                                   │
│  ┌─────────────────────────────────────────────────────────┐             │
│  │ # 简单内存字典                                          │             │
│  │ _request_timestamps = defaultdict(float)               │             │
│  │                                                         │             │
│  │ # 在 POST /api/v1/reports 端点检查                      │             │
│  │ client_ip = request.client.host                        │             │
│  │ last_request = _request_timestamps[client_ip]          │             │
│  │ time_diff = time.time() - last_request                │             │
│  │                                                         │             │
│  │ if time_diff < 30:                                     │             │
│  │     raise HTTPException(429, "请求过于频繁,请30秒后重试")│             │
│  │                                                         │             │
│  │ _request_timestamps[client_ip] = time.time()           │             │
│  └─────────────────────────────────────────────────────────┘             │
│                                                                           │
│  特点：                                                                   │
│  • 仅针对 POST /api/v1/reports 端点                                       │
│  • 基于客户端IP（request.client.host）                                   │
│  • 内存存储（服务重启清零）                                               │
│  • 防止单个用户频繁提交任务                                               │
│                                                                           │
└───────────────────────────────────────────────────────────────────────────┘

┌───────────────────────────────────────────────────────────────────────────┐
│                          FileLock文件锁保护                                │
├───────────────────────────────────────────────────────────────────────────┤
│                                                                           │
│  目的：防止多个进程/线程同时读写同一文件                                  │
│                                                                           │
│  应用场景：                                                               │
│  1. 渲染PPTX文件                                                          │
│     with FileLock(report_path, timeout=60):                              │
│         ppt_generator.render(slidespec, report_path)                     │
│                                                                           │
│  2. 保存SlideSpec JSON                                                   │
│     with FileLock(slidespec_path, timeout=60):                           │
│         slidespec.save(slidespec_path)                                   │
│                                                                           │
│  3. 任务状态更新                                                          │
│     with FileLock(job_state_path, timeout=30):                           │
│         job_store.update_job(job_id, ...)                                │
│                                                                           │
│  实现：                                                                   │
│  • 基于文件系统的跨进程锁（创建.lock文件）                                │
│  • 超时机制 (默认30-60秒)                                                 │
│  • 自动释放 (with语句结束)                                                │
│  • 启动时自动清理超过5分钟的陈旧锁                                        │
│                                                                           │
└───────────────────────────────────────────────────────────────────────────┘

┌───────────────────────────────────────────────────────────────────────────┐
│                          Session会话隔离                                   │
├───────────────────────────────────────────────────────────────────────────┤
│                                                                           │
│  目的：每个请求独立的工作目录，避免冲突                                   │
│                                                                           │
│  Session ID生成：                                                         │
│  ┌─────────────────────────────────────────────────────────┐             │
│  │ uuid_part = uuid.uuid4().hex[:8]                        │             │
│  │ timestamp = datetime.now().strftime('%Y%m%d%H%M%S%f')   │             │
│  │ session_id = f"{uuid_part}_{timestamp}"                │             │
│  │                                                         │             │
│  │ 示例: a3f2c5d8_20250129143022123456                     │             │
│  └─────────────────────────────────────────────────────────┘             │
│                                                                           │
│  目录结构：                                                               │
│  outputs/                                                                 │
│  ├── sessions/                                                            │
│  │   ├── a3f2c5d8_20250129143022123456/                                  │
│  │   │   ├── uploaded.xlsx                                               │
│  │   │   ├── input.json                                                  │
│  │   │   ├── report_mss_executive_v2.pptx                                │
│  │   │   └── slidespec_mss_executive_v2.json                             │
│  │   └── b7e1d4f2_20250129143105987654/                                  │
│  │       └── ...                                                          │
│  ├── jobs/                                                                │
│  │   ├── states/                                                          │
│  │   │   ├── {job_id}.json                                               │
│  │   │   └── ...                                                          │
│  │   └── index.json                                                      │
│  ├── previews/                                                            │
│  │   └── {job_id}/                                                        │
│  │       └── slide*.png                                                  │
│  └── logs/                                                                │
│      ├── app.log                                                          │
│      ├── app.log.1                                                        │
│      └── audit.jsonl                                                     │
│                                                                           │
│  清理策略：                                                               │
│  • 启动时：清理超过7天的session                                          │
│  • 手动：DELETE /api/v1/sessions?max_age_hours=168                        │
