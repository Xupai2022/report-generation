## 关键技术点说明

### 1. Excel文件验证三重保障
- **扩展名检查**：只允许 `.xlsx`，拒绝 `.xlsm`（宏Excel）、`.xls`（旧版）、`.csv`
- **MIME类型验证**：防止文件扩展名伪装攻击
- **大小限制**：流式读取，超过10MB立即中断并删除文件

### 2. Excel数据提取映射规则
```
Excel位置          → JSON字段路径
-----------------   ----------------------
A2                 → customer_name
B2:C2              → period.start/end
D2                 → alerts.total
E2:H2              → alerts.by_severity.*
A5:B10             → top_alert_categories[]
A15:E20            → top_incidents[]
```

### 3. AI内容生成智能分批算法
- **token估算**：中文1.5-2字符/token，英文4字符/token
- **分批阈值**：每批 < 6000 tokens（避免API超时）
- **贪心策略**：优先合并小slides，超限则新建batch
- **进度反馈**：30%-60%之间按批次平均分配进度

### 4. 并发控制机制
- **Semaphore限流**：最大3个并发LLM请求
- **FileLock保护**：防止多用户同时写同一文件
- **Session隔离**：每个请求独立的session目录

### 5. 图表渲染双模式架构
| 类型 | 模式 | 定位方式 | 特点 |
|------|------|---------|------|
| `bar_chart`, `pie_chart` | **代码创建模式** | 使用position配置 | 完全新建图表，支持任意位置 |
| `P11_bar`, `P12-P14_pie`, `P15_line`, `P16_combo` | **模板更新模式** | placeholder位置+距离计算 | 更新已有图表，保留手动样式 |

### 6. 错误容错策略
- **AI格式错误5次** → 自动切换mock模式（数据填充）
- **Rate Limit错误** → 返回429 + `auto_retry_with_mock: true` 标记
- **网络连接错误（APIConnectionError）** → 重试（最多4次，每次等待2秒）

#### 场景3：AI接口不通（网络/服务不可用）

触发条件：
- `ENABLE_LLM=true` 且 `use_mock=false`，进入AI生成链路时出现连接/服务异常（如 `APIConnectionError`、上游5xx等）
- OpenAI 侧返回 `RateLimitError`（请求过于频繁/额度限制）

验收标准：
- 后端调用AI接口时按现有重试逻辑执行（最多4次）；最终失败抛出 `LLMGenerationError`
- `/generate` 对非“AI响应格式错误5次”的 `LLMGenerationError`：
  - 限流类错误返回 `429`（`error.code=LLM_RATE_LIMITED`）
  - 其他不可用错误返回 `503`（`error.code=LLM_UNAVAILABLE`）
  - 响应体包含 `auto_retry_with_mock: true` 与 `details.attempts=4/last_error_type/last_error_message`
- 前端收到 `auto_retry_with_mock: true` 后自动二次调用 `/generate` 并强制 `use_mock=true`，生成可用报告：
  - 数据提取类占位符正常填充、图表正常渲染
  - AI生成类占位符使用 fallback 占位文本，PPT渲染/预览/下载流程不中断

修复路径：
- 短期：保持自动回退（或用户手动勾选 `use_mock`）先生成“数据版”报告；待AI恢复后重新生成完整版本
- 排障：检查 `.env` 中 `OPENAI_API_KEY`、`OPENAI_BASE_URL`、`OPENAI_MODEL` 配置与网络连通性；必要时临时设置 `ENABLE_LLM=false`
